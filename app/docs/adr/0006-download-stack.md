# ADR 0006: Стек скачивания музыки (Lidarr + загрузчик + индексатор)

## Контекст

Lidarr — это менеджер музыкальной коллекции, а не торрент-клиент. Он:
- ищет релизы через настроенные индексаторы (трекеры, Usenet);
- отправляет подходящие релизы на скачивание во внешний загрузчик;
- после скачивания импортирует файлы в музыкальную библиотеку.

Сам Lidarr не скачивает файлы и не ищет торренты без настроенного загрузчика и индексаторов.

В текущем `docker-compose.yml` Lidarr уже есть, но без загрузчика и индексаторов он бесполезен: скачивание не работает, файлы не появляются, Navidrome не имеет чего сканировать.

## Проблема

Нужно собрать полный стек для скачивания музыки, чтобы Lidarr мог:
1. Искать релизы через индексатор;
2. Отправлять релизы на скачивание;
3. Импортировать скачанные файлы в общую библиотеку (`/music`),
   откуда Navidrome и Persephone подхватывают их.

## Рассматриваемые варианты загрузчика

| Загрузчик | Плюсы | Минусы |
|-----------|-------|--------|
| **qBittorrent** | Популярен, прост в настройке, хороший Web UI, свободный | Только BitTorrent |
| Transmission | Легковесный, встроен во многие системы | Менее функционален, чем qBittorrent |
| Deluge | Гибкий через плагины | Сложнее в настройке |
| rTorrent | Мощный, консольный | Сложный конфиг |
| Sabnzbd / NZBGet | Для Usenet | Требует платный Usenet-доступ |

## Рассматриваемые варианты индексатора

| Индексатор | Плюсы | Минусы |
|------------|-------|--------|
| **Prowlarr** | Универсальный индексатор для всего стека Arr (Lidarr, Radarr, Sonarr), много трекеров из коробки | Ещё один контейнер |
| Jackett | Проверенное решение, много трекеров | Устаревает, меньше развивается |
| Прямые трекеры в Lidarr | Без лишнего контейнера | Ограниченный выбор, надо настраивать вручную |

## Принятое решение

**Загрузчик: qBittorrent**  
**Индексатор: Prowlarr**

Обоснование:
- qBittorrent — де-факто стандартный выбор для стека Arr, надёжный, с хорошим Web UI.
- Prowlarr обслуживает не только Lidarr, но и будущие Radarr/Sonarr, если проект расширится на видео.
- Оба имеют официальные Docker-образы от `lscr.io/linuxserver`, совместимые с Lidarr по PUID/PGID.

## Последствия

### Положительные
- Полный автономный стек скачивания: от поиска до импорта в библиотеку.
- Файлы скачиваются в `/downloads`, Lidarr импортирует их в `/music`.
- Navidrome сканирует `/music`, Persephone индексирует файлы через Media Indexer.
- Весь стек управляется через один `docker-compose.yml`.

### Отрицательные
- Ещё два контейнера (qBittorrent, Prowlarr) — больше ресурсов.
- Требуется первичная настройка индексаторов (трекеры) и загрузчика в Web UI.

### Риски
- Пользователь должен сам добавить трекеры в Prowlarr и связать с Lidarr.
- Нужен корректный PUID/PGID, чтобы Lidarr мог импортировать файлы, скачанные qBittorrent.

## Связанные компоненты

- `docker-compose.yml` — сервисы `qbittorrent`, `prowlarr`, связанные с `lidarr` через общий volume `/downloads`
- `scripts/setup-arr-stack.js` — скрипт автоматической настройки Arr-стека через REST API
- Переменные окружения: `QBITTORRENT_URL`, `QBITTORRENT_USERNAME`, `QBITTORRENT_PASSWORD`, `PROWLLARR_URL`, `PROWLLARR_API_KEY`, `LIDARR_URL`, `LIDARR_API_KEY` (в `.env.example`)

## Как запустить настройку

После `docker compose up -d` выполните:

```bash
cd app
PROWLLARR_API_KEY=<ключ_из_профиля_prowlarr> \
LIDARR_API_KEY=<ключ_из_профиля_lidarr> \
node scripts/setup-arr-stack.js
```

API-ключи получаются в Web UI каждого приложения: **Settings → General → API Key**.

- Lidarr уже настроен с `LIDARR_URL` и `LIDARR_API_KEY` в `app-environment`

## Статус

Accepted
