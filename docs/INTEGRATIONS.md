# Integrations

**Проект:** Persephone Music
**Статус:** контракты спроектированы; код адаптеров отсутствует
**Связанные документы:** [ARCHITECTURE.md](../ARCHITECTURE.md), [docs/SECURITY.md](SECURITY.md)

---

## 1. Общие правила

1. Каждая внешняя система изолирована адаптером в `app/src/integrations/<name>/`.
2. Бизнес-логика не импортирует HTTP-клиент интеграции напрямую.
3. Адаптер принимает и возвращает внутренние модели Persephone, а не сырые ответы API.
4. Ошибки адаптера классифицируются: `timeout`, `unavailable`, `unauthorized`, `rate_limited`, `invalid_response`, `not_found`.
5. Отказ внешнего сервиса не останавливает воспроизведение локальных файлов.
6. Все вызовы имеют таймауты, ограниченные повторные попытки и логирование без секретов.
7. Внешние идентификаторы не становятся первичными ключами.

## 2. Navidrome

### Назначение

Playback backend и источник библиотеки в рамках возможностей Navidrome.

### Конфигурация

| Переменная | Назначение |
|---|---|
| `NAVIDROME_URL` | базовый URL, доступный из контейнера API |
| `NAVIDROME_USER` | сервисный пользователь для интеграции |
| `NAVIDROME_PASSWORD` | пароль сервисного пользователя |

### Контракт

```js
playbackAdapter.getStream({ userId, mediaAssetId, clientCapabilities });
```

Требования:

- API сам проверяет права пользователя до обращения к Navidrome;
- поддерживаются HTTP Range и перемотка;
- исходный файл не изменяется;
- клиенту не раскрываются внутренние пути и учётные данные Navidrome;
- при недоступности Navidrome API возвращает понятную ошибку, не повреждая историю.

### Ограничения

- Авторизация Navidrome не считается автоматически синхронизированной с авторизацией Persephone.
- Поддержка нескольких музыкальных корней Navidrome требует отдельной проверки перед использованием.
- Subsonic-совместимость — отдельное направление (Stage 8), а не побочный эффект адаптера.

## 3. Lidarr

### Назначение

Управление библиотекой и импортом; не является источником пользовательских данных.

### Конфигурация

| Переменная | Назначение |
|---|---|
| `LIDARR_URL` | базовый URL |
| `LIDARR_API_KEY` | API-ключ, только на сервере |

### Правила

- Lidarr может быть существующим экземпляром пользователя; дубликат не обязателен.
- Persephone не считает наличие релиза в Lidarr гарантией наличия файла.
- Фактическое наличие файла проверяется через `media_assets` и файловую систему.
- Недоступность Lidarr не блокирует воспроизведение и каталог.
- Запросы на получение контента делегируются менеджеру импорта через адаптер, а не привязываются к конкретному загрузчику.

## 4. MusicBrainz

### Назначение

Основной внешний источник музыкальных идентификаторов: artist, recording, release, release group.

### Конфигурация

| Переменная | Назначение |
|---|---|
| `MUSICBRAINZ_USER_AGENT` | обязательный User-Agent с названием проекта и контактом |
| `MUSICBRAINZ_BASE_URL` | по умолчанию публичный API |

### Правила

- Соблюдать rate limit публичного API (не более одного запроса в секунду) и правила MusicBrainz.
- Использовать кэш и фоновые задачи вместо синхронных вызовов в пользовательском запросе.
- Повторные попытки — с экспоненциальной задержкой.
- MBID хранится как nullable-поле с уникальным ограничением.
- Недоступность MusicBrainz не делает каталог недоступным: метаданные обновляются позднее.
- Ошибочное сопоставление должно исправляться вручную; автоматическое объединение без подтверждения запрещено.

## 5. Last.fm

### Назначение

Персональная интеграция: now playing, scrobbling, похожие исполнители/композиции, теги, история.

Last.fm не является центральной зависимостью: рекомендации используют и собственные данные Persephone.

### Конфигурация

| Переменная | Назначение |
|---|---|
| `LASTFM_API_KEY` | общий ключ приложения |
| `LASTFM_SHARED_SECRET` | общий секрет приложения |
| `LASTFM_BASE_URL` | по умолчанию публичный API |

Пользовательские session keys хранятся в `user_lastfm.session_key_encrypted` и шифруются отдельным ключом окружения `SECRET_ENCRYPTION_KEY`.

### Исходящие операции

- `track.updateNowPlaying` — при старте воспроизведения;
- `track.scrobble` — после выполнения условий скробблинга;
- `track.love` — только если пользователь включил синхронизацию.

### Входящие данные

- похожие исполнители и композиции;
- любимые треки и исполнители;
- история прослушивания;
- популярные треки и исполнители;
- теги и жанровые характеристики.

Точный набор методов фиксируется при реализации адаптера по актуальной документации Last.fm API.

### Очередь и надёжность

- Скробблинг выполняется через BullMQ, не в HTTP-запросе.
- Повторные попытки с ограничением и экспоненциальной задержкой.
- Защита от дублирования: уникальность `(user_id, recording_id, played_at)`.
- Статус синхронизации хранится в `scrobbles` и `user_lastfm`.
- Сбой Last.fm не влияет на воспроизведение.
- Данные одного пользователя никогда не отправляются через session key другого.

### Условия скробблинга

Порог определяется правилами Last.fm и фиксируется в коде как именованная константа с тестами. Ориентир: композиция длиннее 30 секунд и прослушана не менее половины либо 4 минут. Точная реализация — Stage 3 с проверкой актуальных правил.

### Приватность

- Session key не логируется, не возвращается API и не попадает в клиентские ответы.
- При отвязке аккаунта ключ удаляется.
- Ключ шифрования — отдельный секрет, не совпадающий с `SESSION_SECRET`.

## 6. Кэширование внешних данных

Таблица `external_recommendation_cache`:

- ключ: `(source, entity_type, external_id)`;
- payload — нормализованные данные, а не сырой ответ;
- TTL задаётся при записи;
- истёкшие записи очищаются фоновой задачей;
- кэш не является источником истины для пользовательских предпочтений.

## 7. Матрица отказов

| Сервис | Влияние | Поведение |
|---|---|---|
| Navidrome | нет потока | ошибка playback, история не пишется как завершённая |
| Lidarr | нет новых поступлений | библиотека и воспроизведение работают |
| MusicBrainz | нет новых метаданных | каталог доступен, обогащение отложено |
| Last.fm | нет скробблов/похожих | очередь копится, рекомендации используют локальные данные |
| Redis | нет фоновых задач | API работает, ограничения сообщаются явно |
| PostgreSQL | нет состояния | API возвращает `503`, не подменяет данные заглушками |

## 8. Тестирование интеграций

- Unit-тесты адаптеров — на замоканном HTTP-клиенте.
- Контрактные тесты — на записанных ответах (fixtures), без реальных секретов.
- Integration-тесты не должны требовать внешней сети в CI.
- Проверка таймаутов, rate limit и повторных попыток — обязательна.
