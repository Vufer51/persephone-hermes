# Recommendation Engine

**Проект:** Persephone Music
**Статус:** проектирование; реализация — Stage 5
**Связанные документы:** [PROJECT_SPEC.md](../PROJECT_SPEC.md), [docs/DATA_MODEL.md](DATA_MODEL.md), [docs/PREFETCH_ENGINE.md](PREFETCH_ENGINE.md)

## 1. Назначение

Recommendation Engine — собственное интеллектуальное ядро Persephone Music. Он формирует персональные рекомендации на основе данных Persephone, Last.fm и MusicBrainz, но не зависит исключительно от внешнего сервиса.

Рекомендации всегда персональные: одна и та же композиция может быть приоритетной для одного пользователя и неинтересной другому.

## 2. Источники данных

| Источник | Использование |
|---|---|
| История прослушиваний Persephone | основной сигнал интереса |
| Повторные прослушивания | сила предпочтения |
| Завершённые прослушивания | подтверждённый интерес |
| Пропуски | негативный сигнал |
| Время прослушивания | глубина интереса |
| Последовательность композиций | контекст и переходы |
| Любимые композиции | явный положительный сигнал |
| Предпочтения исполнителей | долгосрочный интерес |
| Жанры и теги | тематическая близость |
| Last.fm similar artists/tracks | расширение кандидатов |
| MusicBrainz | связи релизов и исполнителей |
| Реакция на рекомендации | обучение на feedback |

## 3. Конвейер

```text
1. Candidate Generation
        ↓
2. Candidate Filtering
        ↓
3. Ranking
        ↓
4. Diversity
        ↓
5. Explanation
        ↓
6. Feedback loop
```

### 3.1. Candidate Generation

Кандидаты формируются из нескольких независимых источников:

- похожие исполнители Last.fm;
- похожие композиции Last.fm;
- другие записи любимых исполнителей;
- другие релизы недавно прослушанных альбомов;
- жанровые и теговые соседи;
- забытые, но ранее любимые композиции;
- композиции из плейлистов и очередей, если это уместно;
- явные запросы радио.

Каждый кандидат получает `source` и базовый вес источника. Дубликаты объединяются с суммированием вкладов.

### 3.2. Candidate Filtering

Исключаются:

- композиции, недоступные в библиотеке (если политика не предполагает prefetch);
- явные исключения пользователя;
- нежелательные исполнители;
- композиции, прослушанные слишком недавно;
- переигранные композиции (частые повторы);
- уже отклонённые рекомендации в пределах TTL;
- дубликаты одной записи на разных релизах;
- композиции, не прошедшие проверку прав/доступа.

Фильтрация не должна полностью обнулять выдачу: при нехватке кандидатов правила ослабляются контролируемо.

### 3.3. Ranking

Ранжирование — взвешенная функция признаков:

| Признак | Направление |
|---|---|
| Сходство с любимыми исполнителями | + |
| Сходство с недавними прослушиваниями | + |
| Жанровое соответствие | + |
| Личная история (play/skip ratio) | + / − |
| Давность прослушивания | + для rediscovery |
| Свежесть рекомендации | + |
| Штраф за недавний повтор | − |
| Штраф за пропуски | − |
| Штраф за уже показанную рекомендацию | − |

Веса — конфигурируемые параметры, а не магические числа в коде. Значения калибруются на собственных данных и покрываются тестами.

### 3.4. Diversity

После ранжирования применяется перераспределение (например, MMR — Maximal Marginal Relevance):

- ограничение доли одного исполнителя в выдаче;
- ограничение доли одного жанра;
- чередование новизны и знакомых композиций;
- предотвращение «эха» из одной серии релизов.

Цель — не максимальный средний score, а полезная и разнообразная последовательность.

### 3.5. Explanation

Каждая рекомендация может иметь объяснение:

- «похож на любимого исполнителя»;
- «связан с недавно прослушанным альбомом»;
- «найден через Last.fm»;
- «соответствует любимому жанру»;
- «давно не звучал, но раньше нравился».

Объяснение строится по доминирующему вкладу в score и не выдумывает факты. Если объяснение невозможно, поле остаётся пустым.

### 3.6. Feedback

Учитываются:

- воспроизведение рекомендации;
- завершение прослушивания;
- пропуск;
- лайк/дизлайк;
- явное скрытие рекомендации;
- повторный запрос похожего.

Feedback влияет на будущие веса и фильтры, но не переписывает историю.

## 4. Радио

Радио формирует последовательность динамически:

- радио исполнителя;
- радио композиции;
- радио альбома;
- персональное радио;
- радио по жанру;
- радио по плейлисту.

Требования:

- следующая композиция выбирается с учётом уже сыгранного в сессии;
- очередь пополняется заранее (см. Prefetch Engine);
- исключения пользователя соблюдаются;
- разнообразие сохраняется на горизонте сессии;
- при исчерпании кандидатов поведение деградирует предсказуемо, а не повторяет один трек.

## 5. Персональные данные и изоляция

- Все запросы рекомендаций выполняются в контексте `user_id`.
- Кандидаты одного пользователя не влияют на выдачу другого.
- Общие данные каталога используются только как справочник.
- Кэш внешних рекомендаций может быть общим, но ранжирование — всегда персональное.
- Логи не содержат чужих пользовательских данных.

## 6. Производительность

- Генерация выполняется фоновой задачей и сохраняется в `recommendations`.
- Пользовательский запрос читает готовую выдачу, а не запускает тяжёлый расчёт.
- TTL выдачи и batch_id позволяют кэшировать и инвалидировать результаты.
- Тяжёлые внешние вызовы не выполняются синхронно в HTTP-запросе.
- Размер выдачи ограничен; глубина кандидатов — конфигурируемая.

## 7. Оценка качества

Метрики:

- доля рекомендаций, начатых пользователем;
- доля завершённых прослушиваний;
- доля пропусков;
- разнообразие выдачи;
- повторяемость (не рекомендовать одно и то же каждый день);
- покрытие каталога.

Метрики не должны поощрять бесконечное повторение знакомого контента.

## 8. Этапность реализации

1. Простая генерация кандидатов из любимых исполнителей и Last.fm.
2. Персональное ранжирование по истории.
3. Фильтрация и исключения.
4. Разнообразие.
5. Объяснения.
6. Радио.
7. Обучение на feedback.

Не реализовывать сложную модель до появления достаточного объёма собственных данных.

## 9. Ограничения MVP

- Нет коллаборативной фильтрации по другим пользователям.
- Нет ML-модели; используется взвешенная эвристика.
- Нет гарантии наличия файла: рекомендация может приводить к prefetch-задаче.
- Качество зависит от полноты истории и метаданных.

## 10. Открытые вопросы

1. Хранение версий весов и воспроизводимость выдачи.
2. Формат обратной связи от Web Player.
3. Политика «забывания» старых предпочтений.
4. Ограничение нагрузки на Last.fm при генерации.
