# ADR 0005 — Абстракция хранилищ: storage roots + relative path

- **Статус:** Accepted
- **Дата:** 2026-10-31
- **Контекст проекта:** Stage 0

## Контекст

Музыкальные файлы могут находиться на локальных дисках, сетевых хранилищах и в будущем — на нескольких хранилищах одновременно. Абсолютные пути хоста нестабильны и не должны проникать в бизнес-логику.

## Проблема

Как идентифицировать медиафайлы так, чтобы их можно было перемещать между хранилищами без изменения идентичности записи?

## Рассмотренные варианты

1. **Абсолютный путь как идентификатор** — просто, но ломается при переносе и контейнеризации.
2. **Один корень и относительный путь** — лучше, но не поддерживает несколько хранилищ.
3. **`storage_roots` + `relative_path`** — несколько хранилищ, переносимость, явная конфигурация.

## Решение

Принят вариант 3.

- `storage_roots` описывает хранилище: имя, тип, идентификатор, статус.
- `media_assets` хранит `storage_root_id` и `relative_path`.
- Абсолютные пути хоста не сохраняются как основа идентификации.
- Соответствие storage root физическому пути задаётся конфигурацией окружения.
- Одна запись может иметь несколько файлов в разных хранилищах и форматах.

## Последствия

Положительные:

- переносимость библиотеки;
- поддержка нескольких хранилищ;
- возможность перемещения файлов без изменения recording;
- отсутствие утечки путей хоста в API.

Отрицательные:

- дополнительная сущность и проверки;
- необходима валидация, что путь не выходит за пределы root;
- сложнее первичная настройка.

## Ограничения

Поддержка нескольких корней в Navidrome требует отдельной проверки. До подтверждения нельзя предполагать, что backend автоматически поддерживает произвольную схему хранения.
