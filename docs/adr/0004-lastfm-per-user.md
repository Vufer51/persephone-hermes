# ADR 0004 — Last.fm подключается отдельно для каждого пользователя

- **Статус:** Accepted
- **Дата:** 2026-10-31
- **Контекст проекта:** Stage 0

## Контекст

Платформа многопользовательская. Last.fm — важная, но не центральная интеграция. У каждого пользователя может быть собственный аккаунт Last.fm.

## Проблема

Как организовать интеграцию, чтобы действия одного пользователя не влияли на другого и сбой Last.fm не останавливал воспроизведение?

## Рассмотренные варианты

1. **Один общий аккаунт Last.fm** — просто, но нарушает персонализацию и приватность.
2. **Интеграция для каждого пользователя** — отдельные session keys и настройки.
3. **Отказ от Last.fm** — теряется источник персональных данных.

## Решение

Принят вариант 2.

- Общий API key приложения используется для OAuth-подписи.
- Session key каждого пользователя хранится отдельно и шифруется.
- Шифрование использует `SECRET_ENCRYPTION_KEY`, не совпадающий с `SESSION_SECRET`.
- Скробблинг выполняется через очередь BullMQ.
- Сбой Last.fm не блокирует воспроизведение.
- Данные одного пользователя никогда не отправляются через ключ другого.
- Привязка и отвязка аккаунта — явные операции пользователя.

## Последствия

Положительные:

- корректная персонализация;
- изоляция пользовательских данных;
- устойчивость к недоступности Last.fm.

Отрицательные:

- необходимость управления ключами и их ротации;
- больше состояния и фоновых задач;
- риск утечки session key требует шифрования и запрета логирования.

## Ограничения

Last.fm не является источником истины для рекомендаций. Собственные данные Persephone имеют приоритет.
