# ADR 0002 — Original First: воспроизведение без транскодирования в MVP

- **Статус:** Accepted
- **Дата:** 2026-10-31
- **Контекст проекта:** Stage 0

## Контекст

Музыкальная библиотека содержит файлы разных форматов и качества. Транскодирование требует CPU, кэша, управления форматами и повышает сложность MVP.

## Проблема

Как отдавать музыку в первой версии: транскодировать всегда, выбирать качество автоматически или отдавать оригинал?

## Рассмотренные варианты

1. **Always transcode** — единый формат для всех клиентов, высокие требования к CPU.
2. **Adaptive/Auto** — выбор качества по клиенту, сложная логика и кэш.
3. **Original First** — отдавать исходный файл без изменений.

## Решение

Принят вариант 3 для MVP.

- Отдаётся оригинальный файл.
- Поддерживаются HTTP Range и перемотка.
- Аудиоданные не изменяются.
- Производные версии не создаются.
- Схема БД заранее содержит `preferred_format`, `max_bitrate_kbps`, `transcode_policy`, но `transcode_policy` допускает только `source`.

## Последствия

Положительные:

- минимальная сложность и нагрузка;
- максимальное качество;
- нет проблем с кэшем и очисткой;
- поведение предсказуемо.

Отрицательные:

- клиент должен поддерживать формат файла;
- возможен высокий расход трафика;
- пользователи с ограниченной пропускной способностью не могут выбрать качество.

## Ограничения

Будущее транскодирование добавляется как опция с временным кэшем и не изменяет оригиналы. Реализация требует отдельного ADR и не должна имитироваться фиктивными режимами.
